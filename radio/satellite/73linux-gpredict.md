## Objective

Provide native GPSD support in the x86-64 Gpredict
installation supplied by 73Linux.

The Ubuntu Noble distribution package provides Gpredict
2.3 without native GPSD support.

This limits its usefulness for portable amateur radio
operations requiring automatic ground station positioning.

Gpredict 2.6 supports GPSD when compiled against libgps.

No modifications to the upstream Gpredict source code
were necessary.

## Release Management

The recipe uses a pinned upstream release.

```bash
GPREDICT_RELEASE=2.6
GPREDICT_SHA256=f4e6967cb2eeb6d74b8e8208c90dc8f4b1c00955ae1049753ad8352c927e54a3
```

Release archive:

```text
gpredict-2.6.tar.bz2
```

The SHA-256 checksum was recorded from the downloaded
upstream release.

Checksum verification protects against unexpected archive
changes and download corruption.

It does not independently authenticate the upstream
release publisher.

## Installation Lifecycle

The INSTALL function performs these operations:

1. Validate the source directory path.
2. Create the source directory if necessary.
3. Verify source directory ownership.
4. Reject a symbolic link as the source directory.
5. Acquire a nonblocking exclusive lifecycle lock.
6. Install required development dependencies.
7. Create a unique build directory.
8. Download the pinned source archive.
9. Verify the SHA-256 checksum.
10. Extract the verified archive.
11. Configure the source for /usr/local.
12. Compile without elevated privileges.
13. Verify linkage against libgps.
14. Install with elevated privileges.
15. Atomically record the successfully installed build.
16. Release the lifecycle lock upon function exit.

Each installation receives its own build directory.

Existing build directories are not overwritten or
automatically deleted.

## Build Directory Layout

The recipe uses the 73Linux BAPSRC variable.

On reference workstation:

```text
~/.bap-source-files/
```

Representative directory structure:

```text
.bap-source-files/
    gpredict.lock
    gpredict-current -> gpredict-2.6.build.XXXXXX/gpredict-2.6
    gpredict-2.6.build.XXXXXX/
        gpredict-2.6.tar.bz2
        gpredict-2.6/
            Makefile
            src/
            data/
            doc/
            icons/
            pixmaps/
            po/
```

The actual build directory suffix is generated by mktemp.

The gpredict-current symbolic link identifies the source
tree associated with the latest successful installation.

The configured source tree must be retained for removal.

## Concurrency Management

INSTALL and REMOVE execute within Bash subshell functions.

Both functions acquire an exclusive advisory lock using
flock.

The lock is associated with:

```text
${BAPSRC}/gpredict.lock
```

Concurrent operations using the same source directory
are rejected rather than allowed to interfere.

The lock is released when the subshell and any processes
retaining its lock descriptor terminate.

The lock file itself remains present between operations.

Its existence does not indicate that an operation is
currently running.

## Privilege Separation

Source acquisition, checksum verification, extraction,
configuration, and compilation occur under the normal
user account.

Elevated privileges are used for dependency installation,
system-wide installation, and system-wide removal.

The recipe follows the existing 73Linux sudo -A convention.

## Version Detection

VERSION executes in the calling shell so that its
CURRENT and NEWVER variables remain available to 73Linux.

For a source installation, the installed NEWS file is
examined to identify the release.

For a distribution installation, the package version is
obtained using dpkg-query.

When neither installation is detected, CURRENT is zero.

Version detection is not a comprehensive installed-file
integrity check.

## Removal Lifecycle

The REMOVE function:

1. Validates the source directory.
2. Acquires the lifecycle lock.
3. Locates the recorded source build.
4. Executes make uninstall for the source installation.
5. Removes four residual upstream documentation files.
6. Removes the distribution package if installed.
7. Removes the active build symbolic link.
8. Preserves user configuration.
9. Retains source build directories for diagnostics.

Development dependencies are not automatically removed.

The recipe does not perform apt autoremove.

## Failure Injection Methodology

Failure tests were executed by sourcing the recipe in an
isolated Bash subshell.

The complete 73Linux installer was not executed.

### Checksum Failure

The expected SHA-256 checksum was deliberately replaced
with an invalid value.

The recipe downloaded the source archive, rejected the
checksum, and terminated before extraction.

No executable or active build link was created.

### Compilation Failure

The make command was overridden with a Bash function
returning a nonzero exit status.

Download, checksum verification, extraction, and source
configuration completed normally.

The recipe detected the compilation failure and exited
before installation.

### Privileged Installation Failure

The sudo command was overridden to reject make install.

Actual source compilation completed successfully.

The recipe returned a nonzero exit status without
creating an active build link.

This test simulated failure before installation writes.

It did not simulate a partially completed privileged
installation.

### Lock Contention

An external process acquired the lifecycle lock.

Both INSTALL and REMOVE rejected concurrent execution.

The lock became available after the external lock
descriptor was closed.

## Recovery Procedures

### Download or Compilation Failure

Inspect the retained build directory and diagnostic output.

Correct the underlying problem and repeat installation.

The next installation creates a new isolated build tree.

### Privileged Installation Failure

The final recipe reports the source directory associated
with the failed installation.

A failed privileged installation may leave partially
installed files under /usr/local.

The recipe does not implement transactional rollback.

For a first installation that failed without a previous
source installation, the retained build directory can be
used for manual recovery.

Inspect the failure and correct its cause.

From the exact retained source directory:

```bash
sudo make uninstall
```

Remove residual Gpredict documentation files as described
in gpredict.md if necessary.

Then repeat installation using the recipe.

If an earlier source installation was present, uninstalling
the failed build may also remove files belonging to that
installation. Plan to reinstall the desired release.

Do not assume that a failed upgrade leaves the previously
installed application intact.

These procedures are recovery guidance. Actual partial
installation rollback has not been validated.

### Missing Build Directory

If the active source build directory has been deleted,
the original make uninstall metadata is unavailable.

Do not remove arbitrary files from /usr/local.

For a Gpredict 2.6 installation managed by this recipe,
reinstalling the same release should recreate the required
uninstallation metadata.

Then remove the application using the revised recipe.

This recovery procedure has not been independently tested.

## Known Limitations

The recipe does not implement transactional installation
or automatic rollback.

Removal depends on retaining the configured source tree.

A privileged installation can modify installed files
before returning an error.

An interruption between successful installation and
active-link replacement can leave stale or missing
installation tracking.

Version detection does not verify every installed file.

Lifecycle locking applies only to operations sharing
the same BAPSRC directory.

Build directories accumulate and require deliberate
maintenance.

Cross-version source upgrades have not been validated.

Raspberry Pi compatibility has not been validated.

The complete 73Linux installer integration has not been
exercised during these isolated recipe tests.
